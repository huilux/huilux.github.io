通义千问

xinitrc 是一个脚本文件，主要用于自定义和控制 X Window 系统启动时的行为。全名中的 “xinit” 指的是启动 X 服务器的程序，而 “rc” 代表 runtime configuration（运行时配置）。当你启动 X Window 系统时，xinit 或者 startx 命令会执行 ~/.xinitrc（用户级别的配置）或者 /etc/X11/xinit/xinitrc（系统级别的配置）脚本。

这个脚本中可以包括一系列命令来定义启动哪些程序、设置环境变量、定义窗口管理器、桌面环境或者是简单的 xterm 终端等。它是高度可定制的，允许用户根据个人偏好设置图形界面的启动过程。

具体来说，xinitrc 文件中可能包含以下类型的命令：

  • 启动一个或多个终端模拟器，如 xterm。
  • 启动窗口管理器（Window Manager，如 i3, dwm, XFCE, KDE 等）或桌面环境（Desktop Environment，如 GNOME, KDE Plasma 等）。
  • 设置环境变量，影响图形应用的行为。
  • 运行其他自定义脚本或命令来准备图形环境。

通过 SDDM 启动 DWM

如果你的dwm是通过自己 make install 安装的，不会在/usr/share/xsessions生成一个dwm.desktop文件，那么也就无法在 SDDM 显示管理器中找到 dwm 的启动菜单了

手动添加这个文件：/usr/share/xsessions/dwm.desktop

[Desktop Entry]
Encoding=UTF-8
Name=Dwm
Comment=Dynamic window manager
Exec=dwm
Icon=dwm
Type=XSession

然后设置系统的默认运行级别为图形界面模式，并自启动SDDM

$ systemctl set-default graphical.target
$ systemctl enable sddm.service

reboot 后将在 SDDM 显示管理器中找到 dwm 的启动项了，但是从这里启动后似乎没有加载~/.xinitrc配置文件

dpmsQuickOff 的作用:

控制显示器是否在屏幕保护程序启动时立即进入关闭状态，而不等待 dpmsStandby、dpmsSuspend 或 dpmsOff 所定义的时间延迟

安装xorg-xset包，可以使用xset -q查看锁屏状态

xset dpms force standby强制进入待机模式 xset dpms force suspend强制进入休眠模式 xset dpms force off强制关闭显示器

模式功耗恢复速度主要用途
待机模式较低功耗快速恢复短时间离开时使用，快速唤醒显示器。
暂停模式更低功耗较快恢复较长时间离开时使用，平衡恢复速度和功耗。
完全关闭最低功耗恢复最慢长时间离开或非工作时间段使用，节能优先。

注意： Display Power Management Signaling (DPMS) 的暂停模式（Suspend Mode）和系统的挂起操作（Suspend 或 Sleep）虽然名字相似，但它们的作用和范围不同，不能完全等同

特性DPMS 暂停模式系统挂起（Suspend/Sleep）
作用范围仅显示器整个系统（CPU、内存、硬盘等）
硬件状态显示器部分硬件暂停工作系统大部分硬件暂停工作
功耗显示器降低功耗，但系统仍运行系统整体功耗显著降低
唤醒方式鼠标移动、按键唤醒显示器鼠标、键盘或电源按钮唤醒系统
恢复速度几秒钟内需要更长时间（几秒到十几秒）
是否保存工作状态不影响系统运行保存工作状态

为什么我运行systemctl status pulseaudio.service提示找不到服务，原因：PulseAudio 通常作为用户服务运行，而不是系统服务。这意味着它在每个用户会话中单独启动，并且管理用户级别的配置和状态

$ systemctl --user status pulseaudio.service

$ pulseaudio --start
# 停止 PulseAudio

  • pulseaudio-equalizer包 用于均衡器接收器 (qpaeq)
  • pulseaudio-jack包 用于 JACK sink、source 和 jackdbus 检测

麦克风回声/噪音消除

Arch 默认不会加载 PulseAudio 的回声消除模块，因此，我们需要在/etc/pulse/default.pa.d/中添加它。首先，你可以使用 pacmd 并输入list-modules。如果你无法找到 name: <module-echo-cancel>，你就需要创建一个。

/etc/pulse/default.pa.d/noise-cancellation.pa
### 启用回声消除
load-module module-echo-cancel use_master_format=1 aec_method=webrtc aec_args="analog_gain_control=0\ digital_gain_control=1" source_name=echoCancel_source sink_name=echoCancel_sink
set-default-source echoCancel_source
set-default-sink echoCancel_sink

#!/bin/bash
# amixer sget Master | awk -F "[][]" ' /Mono:/ { print $2 }'
# amixer sget Master | awk -F "[][]" '/Front Left:/ { print $2 }'
#
# 获取默认输出设备(比如扬声器)
default_sink=$(pactl info | grep "Default Sink" | awk '{print $3}')

# 获取默认输入设备(比如麦克风)
default_source=$(pactl info | grep "Default Source" | awk '{print $3}')

# 得到默认输出设备的音量百分比
volume=$(pactl list sinks | grep -A 10 ${default_sink} | grep '^[[:space:]]*Volume:' | awk '{print $9}' | grep -v '^$')

# 得到默认输出设备的开启情况
mute_sink=$(pactl list sinks | grep -A 10 ${default_sink} | grep '^[[:space:]]*Mute:' | awk '{print $2}' | grep -v '^$')

# 得到默认输入设备的开启情况
mute_source=$(pactl list sources | grep -A 10 ${default_source} | grep '^[[:space:]]*Mute:' | awk '{print $2}' | grep -v '^$')


echo "${volume}/${mute_sink}-Mic:${mute_source}"

于是启动geoclue服务：systemctl start geoclue.service，在启动服务前需要修改其配置文件/etc/geoclue/geoclue.conf

[redshift]
allowed=true
system=false
users=

注：geoclue 服务需要连接到Avahi-Daemon守护进程，因此还要启动：systemctl start avahi-daemon.service

Avahi-Daemon 是一个实现了 Zeroconf 协议的守护进程，它主要用于在局域网内广播或发现服务和设备，简化网络服务的发现过程。Geoclue 有时会尝试使用 Avahi 来发现本地网络上的位置服务提供者，比如特定的路由器或设备，以辅助进行网络定位

手动配置

Redshift 会读取配置文件 ~/.config/redshift/redshift.conf

[redshift]

; Set the location-provider: 'geoclue2', 'manual'
; type 'redshift -l list' to see possible values.
; The location provider settings are in a different section.
location-provider=manual


; Keep in mind that longitudes west of Greenwich (e.g. the Americas)
; are negative numbers.
[manual]
lat=31.889
lon=120.6836

编写脚本启动redshift

#!/bin/bash
killall redshift
if [ $? != 0 ];then
 kstart5 redshift
fi

启动管理器

启动管理器会读取哪些文件夹的desktop文件？

  1. 用户专属目录：$XDG_DATA_HOME/applications

    若系统未手动配置$XDG_DATA_HOME环境变量，默认路径就是~/.local/share/applications/。这个目录存放当前用户专属的.desktop文件，比如用户级安装的 Flatpak 应用、手动创建的自定义应用启动配置等

  2. 系统全局目录：$XDG_DATA_DIRS/applications

    # 查看 XDG_DATA_DIRS
$ echo $XDG_DATA_DIRS
/home/ming/.local/share/flatpak/exports/share:/var/lib/flatpak/exports/share:/usr/local/share:/usr/share

  3. Flatpak 专属导出目录：该路径通常会被纳入系统的XDG_DATA_DIRS相关查找范围，比如上面的/var/lib/flatpak/exports/share

QQ

linuxqq-nt-bwrap

==== linuxqq-nt-bwrap 注意事项 ====
==> 要传递给 bwrap 的自定义参数应该写在 ~/.config/qq-bwrap-flags.conf，
    可在此文件中设置自定义挂载目录。
==> 要传递给 electron 的自定义参数应该写在 ~/.config/qq-electron-flags.conf。
==> 如果要在 QQ 中下载文件，请先在 设置 -> 存储管理 中
    把下载文件夹更改为系统的“下载”/“Downloads”文件夹。
==> 如果系统中安装了 Docker / ZeroTier / Tailscale 或配置了 TUN / TAP 网络设备，
    则可以使用固定 MAC 地址模式启动 QQ 以修复自动登录问题。
    当系统有上述网络设备时，安装 slirp4netns 和 socat 包再启动 QQ 即可使用此模式。
    如果未安装上述网络设备，你也可以在 ~/.config/qq-fix-mac.conf 中写入任意内容，
    或设置 QQ_FIX_MAC 环境变量为 1 来手动启用此模式。
Optional dependencies for linuxqq-nt-bwrap
    libappindicator-gtk3: 以显示托盘图标 [installed]
    gjs: 提供 GNOME Wayland 下的截图支持 [installed]
    slirp4netns: 固定 MAC 地址时需要
    socat: 固定 MAC 地址时需要 [installed]
