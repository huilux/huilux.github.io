按官方流程重建 Huilux

记录如何使用 Hugo 官方命令创建项目和主题，并建立支持任意深度目录的知识博客。

发布2026/07/27· 28 天前更新2026/07/28· 28 天前阅读约 17 分钟字数5,751 字
  • #Hugo
  • #博客
  • #主题开发
内容时效

本文最后维护于28 天前，部分技术细节可能已经变化，请结合当前版本和官方文档核对。

这篇文章记录 Huilux 当前版本的实际创建过程。项目使用 Hugo 官方生成器，本地主题名为 huilux-tree。网站渲染不依赖 Node.js、远程字体或第三方前端框架；主题中的 Node.js 依赖只用于开发期的代码格式化和 Git 提交检查。

确认 Hugo 版本

首先确认本机安装的是 Hugo Extended：

hugo version

本站创建时使用：

hugo v0.164.0+extended

使用官方命令创建项目

Hugo 当前的项目创建命令是 hugo new project；旧的 hugo new site 仍然是它的兼容别名。

cd /home/ming/blog
hugo new project huilux --format toml
cd huilux

生成的基础结构包括：

huilux/
├── archetypes/
├── assets/
├── content/
├── data/
├── i18n/
├── layouts/
├── static/
├── themes/
└── hugo.toml

创建本地主题

在项目根目录执行：

hugo new theme huilux-tree --format toml

然后在站点的 hugo.toml 中启用：

theme = "huilux-tree"

所有布局、样式、脚本和短代码都放在 themes/huilux-tree/ 中；站点根目录只保存内容和站点配置，因此主题可以独立维护或复用。

站点与主题是两层项目

理解目录前，先区分两个容易混淆的 hugo.toml 和两层职责：

huilux/                         # 站点项目：保存内容和站点配置
├── hugo.toml                   # 启用主题、菜单、Markdown、参数等
├── content/                    # 博客文章与栏目
├── static/                     # 站点自己的静态文件
├── public/                     # Hugo 构建结果
└── themes/
    └── huilux-tree/            # 主题项目：决定页面如何显示和交互
        ├── hugo.toml           # 只声明主题要求的 Hugo 版本
        ├── layouts/            # HTML 模板
        ├── assets/             # 经过 Hugo Pipes 处理的 CSS 和 JavaScript
        └── static/             # 主题直接提供的 favicon

站点根目录的 hugo.toml 是网站的实际配置入口，其中 theme = "huilux-tree" 把两层连接起来。主题自己的 hugo.toml 不是第二份站点配置，它只声明主题要求 Hugo Extended 且最低版本为 0.164.0。

Hugo 会合并站点和主题中名称相同的目录，站点文件优先。例如：

  • layouts/page.html 若出现在站点根目录，会覆盖主题的同名文章模板；
  • assets/css/main.css 若出现在站点根目录，会成为 Hugo 资源查找时优先命中的文件；
  • static/favicon.svg 若出现在站点根目录，会覆盖主题提供的 favicon；
  • content/ 属于站点本身，主题不保存实际文章。

因此，小范围定制可以放在站点根目录覆盖主题；希望所有使用者都获得的能力，则应该修改 themes/huilux-tree/。

下面是 themes/huilux-tree/ 当前有意义的完整结构。.git/ 和 node_modules/ 内部包含大量由工具管理的文件，因此只展示目录本身：

根目录文件与开发工具

README.md

主题的开发入口文档，记录最低 Hugo 版本、格式检查命令、完整站点构建命令，以及重新生成 Chroma 样式的方法。它面向维护主题的人，不会进入最终网站。

hugo.toml

主题模块描述文件，目前只有：

[module]
[module.hugoVersion]
extended = true
min = '0.164.0'

它表达两个约束：主题最低支持 Hugo 0.164.0，并需要 Extended 版本。Extended 在这里主要用于保证 Hugo 的完整资源处理能力。站点标题、菜单、主题参数等仍由站点根目录的 hugo.toml 决定。

package.json

Node.js 只承担主题源码维护工作，没有参与浏览器运行，也没有打包网站：

  • prettier 统一格式化 Markdown、CSS、JavaScript、JSON 等文件；
  • prettier-plugin-go-template 让 Prettier 理解 Hugo 的 Go Template 语法；
  • prettier-plugin-toml 负责 TOML；
  • pretty-quick 只检查 Git 暂存区中的文件；
  • simple-git-hooks 安装 pre-commit hook，在提交前执行 npm run format:staged；
  • npm run format 写入格式化结果，npm run format:check 只检查而不修改。

Hugo 自己完成 CSS、JavaScript 的拼接、压缩和指纹计算，所以这里不需要 Vite、Webpack 或其他前端构建器。

package-lock.json

锁定所有直接、间接 npm 开发依赖的精确版本与完整性哈希，使不同机器上的 npm install 得到相同工具链。它应随 package.json 一起提交，并由 npm 更新，不应手工编辑。

.prettierrc.json

Prettier 的具体规则：

  • 加载 Go Template 和 TOML 插件；
  • 行宽为 100；
  • Markdown 保持原有换行；
  • JavaScript 等使用单引号；
  • *.html 强制使用 go-template 解析器，避免把 {{ ... }} 当成普通 HTML。

.prettierignore

排除不适合格式化的内容：

  • node_modules/：第三方依赖；
  • public/：Hugo 构建结果；
  • resources/_gen/：Hugo 资源缓存；
  • assets/css/chroma.css：由 Hugo 命令生成的 CSS；
  • static/favicon.ico：二进制图标。

.gitignore

忽略 .hugo_build.lock、node_modules/、public/ 和 resources/_gen/。这些内容都能由 Hugo 或 npm 重新生成，不属于主题手写源码。

.git/

保存主题自己的提交历史、分支、索引和 hook。它说明 huilux-tree 可以作为一个独立 Git 仓库维护。这里的内容由 Git 管理，不应手工修改，也不属于 Hugo 主题源码。

.hugo_build.lock

Hugo 启动构建或开发服务器时使用的临时锁文件，用来协调构建过程。当前文件为空是正常现象；它已经被 .gitignore 排除，不需要维护。

node_modules/

npm install 生成的本地开发依赖目录。当前内容只服务于 Prettier 和 Git hook，网站打开时不会下载或执行这里的包。删除后可以用 npm install 重新生成，因此不逐个解释其中的第三方文件。

内容原型

archetypes/default.md

执行 hugo new content ... 时使用的默认文章模板，会自动填入创建时间、草稿状态和根据文件名生成的标题：

+++

+++date = '{{ .Date }}'
draft = true
title = '{{ replace .File.ContentBaseName "-" " " | title }}'

站点根目录也有同名 archetypes/default.md，站点版本优先；主题中的文件是主题独立复用时的后备默认值。

前端资源

assets/ 中的文件不会像 static/ 一样原样复制。它们先通过 resources.Get 进入 Hugo Pipes，再由模板决定输出方式。

assets/css/chroma.css

保存 Hugo Chroma 语法高亮器生成的两套规则：

  • .light 根类下使用 GitHub 风格的亮色高亮；
  • .dark 根类下使用 GitHub 风格的暗色高亮。

文件开头和中部的注释保留了完整生成命令。它是“纳入版本控制的生成物”：应该提交，但更换配色时应重新执行 hugo gen chromastyles，而不是逐条手改。站点必须设置 markup.highlight.noClasses = false，Chroma 才会输出这些 CSS 所需的类名。

assets/css/main.css

主题的主样式文件，大致按以下职责排列：

  1. 在 :root 中定义颜色、阴影、字体栈、三栏宽度等设计变量；
  2. 在 html[data-theme="dark"] 中覆盖暗色变量；
  3. 定义全局重置、无障碍辅助类和键盘跳转链接；
  4. 实现顶栏、三栏布局、左右侧栏、知识树与本页目录；
  5. 实现首页 Hero、目录卡片、文章列表、文章头部与正文排版；
  6. 实现标题级别标记、表格、引用、图片、行内代码和代码块工具栏；
  7. 为 admonition、typeit、标签页、404 和页脚提供样式；
  8. 在 1180px、860px、560px 三个断点切换侧栏和移动端布局；
  9. 通过 prefers-reduced-motion 尊重用户的“减少动态效果”设置。

字体全部来自本机字体栈，没有请求远程字体。亮暗主题也主要通过 CSS 变量切换，避免维护两套组件规则。

assets/js/main.js

一个立即执行的原生 JavaScript 模块，负责所有渐进增强交互：

  • 根据系统偏好和本地记录切换亮色、暗色主题，并同步浏览器 theme-color；
  • 在桌面端折叠侧栏，在窄屏上把侧栏改为抽屉，支持遮罩和 Escape 关闭；
  • 保存、恢复左侧目录树中各文件夹的展开状态；
  • 递归筛选文件树标题，按 / 可直接聚焦搜索框；
  • 为旧内容中未经过新渲染钩子的代码块补上统一工具栏；
  • 复制代码，并在 Clipboard API 不可用时使用兼容方案；
  • 折叠、展开代码块并维护正确的无障碍属性；
  • 使用 IntersectionObserver 高亮右侧目录中当前阅读的标题。

它读写四类 localStorage 键：

键保存内容
huilux-color-themelight 或 dark
huilux-sidebar-left左侧栏的桌面折叠状态
huilux-sidebar-right右侧栏的桌面折叠状态
huilux-tree-open各目录 URL 与展开状态组成的 JSON

脚本对本地存储、剪贴板等 API 都有失败回退；禁用 JavaScript 时文章与导航链接仍可访问，只会失去折叠、搜索、复制等增强功能。

页面布局模板

Hugo 根据页面种类选择对应模板。除 baseof.html 外，这些模板都只定义名为 main 的区块，再由基础模板包裹成完整 HTML。

layouts/baseof.html

所有页面共同的骨架，主要工作是：

  • 输出 <!doctype html>、html、head 和 body；
  • 检查普通文章的 .TableOfContents 是否真的包含列表项；
  • 根据页面种类添加 kind-*，没有目录时再添加 no-page-toc；
  • 调用 head、顶栏、左侧栏、页脚等公共 partial；
  • 提供子模板要填充的 main block；
  • 只在文章有目录时渲染右侧栏；
  • 输出移动端侧栏共用的遮罩按钮。

这是三栏布局的汇合点，也是追踪一张页面由哪些组件组成时最先看的文件。

layouts/home.html

首页主体，分为三部分：

  • Hero：显示当前日期、站点描述和“最近更新”锚点；
  • 分类：读取 site.Home.Sections，以目录卡片显示一级栏目；
  • 最近更新：从 site.RegularPages 中排除 navHidden: true 的页面，再按 Lastmod 倒序取前 12 篇。

目录和文章卡片本身分别交给 cards/directory.html 与 cards/article-row.html。

layouts/page.html

普通文章页：

  • 显示面包屑、所属顶级栏目、发布日期、标题和描述；
  • 显示更新时间、阅读时间、字数和标签；
  • 将 Markdown 渲染结果 .Content 放入 .prose.article-body。

其中只有 .Lastmod 与 .Date 不同时才显示“更新于”。

layouts/section.html

由 _index.md 表示的栏目或目录页：

  • 页头展示标题、描述、栏目正文和递归文章总数；
  • .Sections 以卡片展示直接子目录；
  • .RegularPagesRecursive 列出当前目录以及所有后代目录中的文章；
  • 子目录和文章都通过 page-groups.html 应用统一排序规则。

layouts/taxonomy.html

分类法总览模板。本站只启用了 tags，所以它实际生成标签首页 /tags/，按字母顺序显示所有标签及每个标签的文章数。

layouts/term.html

单个分类项模板。对本站而言就是某个具体标签页，例如 /tags/hugo/；它按发布日期倒序列出带有该标签的文章。

layouts/404.html

未找到页面时使用的主体模板，提供错误说明和返回首页链接。它仍复用 baseof.html，所以保留站点顶栏、侧栏和页脚。

可复用局部模板

layouts/_partials/ 用来拆分公共 HTML。调用 partial 时要留意传入的上下文：多数文件接收当前页面 .，header.html 接收一个同时包含页面和目录状态的字典，树节点则接收 node 与 current。

页面框架组件

文件作用
_partials/head.html生成字符集、视口、页面标题、描述、作者、canonical、favicon 和 RSS 链接；在加载样式前内联一小段主题初始化脚本，避免暗色模式闪白；最后调用 CSS、JavaScript 资源 partial。
_partials/header.html生成左侧栏开关、品牌、由 site.Menus.main 驱动的顶栏导航、颜色主题开关，以及有目录时才出现的右侧栏开关。
_partials/footer.html显示站点版权、Hugo 链接和状态文案。
_partials/breadcrumbs.html通过 .Ancestors.Reverse 从首页到当前页面生成层级不限的面包屑，并为当前项设置 aria-current。
_partials/terms.html根据传入的分类法名称调用 .GetTerms，当前由文章页用来渲染标签链接。

CSS 与 JavaScript 资源管线

文件作用
_partials/head/css.html获取 chroma.css 和 main.css，拼接为 css/site.css。开发环境直接引用；正式构建时再压缩、计算内容指纹，并输出带 SRI integrity 的链接。
_partials/head/js.html获取 main.js。开发环境直接引用；正式构建时压缩、加指纹和 SRI，并始终使用 defer，不阻塞 HTML 解析。

两者都由 partialCached 调用，因为同一次构建中资源结果对所有页面相同，没有必要为每篇文章重复计算。

列表卡片与排序函数

文件作用
_partials/cards/directory.html一张目录卡片，显示目录名、递归文章数、直接子目录数和链接。首页、栏目页共同复用。
_partials/cards/article-row.html一行文章摘要，显示日期、父目录、标题、描述或自动摘要，以及两个文章链接。首页、栏目页、标签页共同复用。
_partials/functions/page-groups.html纯数据 partial。把传入页面拆成显式设置 weight 的 manual 和未设置的 automatic 两组；前者按 Weight 升序，后者按 Date 降序，并用 return 返回字典。

“显式设置 weight 的内容优先”不是 Hugo 的默认偶然结果，而是 page-groups.html 明确实现的主题规则。

左右侧栏与递归知识树

文件作用
_partials/sidebar/left.html左侧知识树入口。显示文章总数和可选搜索框，获取首页全部一级 .Sections，排序后逐个调用 tree/folder.html。params.treeSearch 控制搜索框是否输出。
_partials/tree/folder.html一个目录节点，也是递归核心。判断目录是否为当前页或祖先，生成稳定 ID，先递归渲染子目录，再渲染直接文章，因此目录永远排在文章前面。
_partials/tree/file.html一个叶子文章节点，生成文章链接，并在当前文章上设置 is-current 与 aria-current="page"。
_partials/sidebar/right.html输出 Hugo 生成的 .TableOfContents 和“回到顶部”链接；是否调用该文件由 baseof.html 判断。

folder.html 调用自身时，每深入一级都会继续读取下一层 .Sections，所以树的深度由内容结构决定，没有写死二级或三级上限。

Markdown 渲染扩展

layouts/_markup/render-codeblock.html

这是 Goldmark 围栏代码块的渲染钩子。它在 Hugo 构建期：

  1. 读取代码语言，不存在或为 fallback 时显示 TEXT；
  2. 检查 Chroma 是否认识该语言，未知语言按纯文本处理；
  3. 调用 transform.HighlightCodeBlock 获得高亮 HTML；
  4. 为每个代码块生成唯一 ID；
  5. 输出语言、折叠按钮、复制按钮及代码正文所需的语义结构。

构建期模板负责正确 HTML，main.js 再负责按钮交互。旧文章中不是由该钩子生成的 <pre> 或 .highlight，也会由脚本包装成近似结构。

layouts/_shortcodes/admonition.html

兼容旧博客的提示框短代码。第一个位置参数决定 note、warning 等类型，title 可改标题，open="false" 可让 <details> 默认折叠，内部 Markdown 通过 markdownify 渲染。

layouts/_shortcodes/typeit.html

兼容旧博客的 TypeIt 短代码，但不再加载打字动画库，而是输出静态内容：

  • 有 code 参数时输出带语言类名的 <pre><code>；
  • 否则使用 tag 参数指定标签，默认是 <span>；
  • 内容会去掉首尾空白，普通文本分支再经过 Markdown 渲染。

这两个短代码的目的都是让迁移来的旧文章继续构建，而不必把全部历史内容一次性改写。

主题静态文件

static/favicon.svg

现代浏览器使用的矢量站点图标，由 head.html 显式链接。它从主题的 static/ 原样复制到构建结果根目录的 /favicon.svg。

static/favicon.ico

提供给仍会自动请求 /favicon.ico 的浏览器和工具，包含 16×16 与 32×32 等位图尺寸。它同样原样复制，不进入 Hugo Pipes；因为是二进制文件，也被 Prettier 排除。

一篇文章的实际渲染链路

以 content/博客建设/Hugo/按官方流程重建Huilux/index.md 为例：

index.md 与 Front Matter
        │
        ▼
站点 hugo.toml：启用主题、Goldmark、Chroma、目录和菜单
        │
        ▼
layouts/page.html：定义文章主体 main
        │
        ▼
layouts/baseof.html：组装完整页面
        ├── _partials/head.html
        │   ├── head/css.html ── chroma.css + main.css
        │   └── head/js.html  ── main.js
        ├── _partials/header.html
        ├── _partials/sidebar/left.html
        │   └── tree/folder.html ⇄ 递归调用自身
        │       └── tree/file.html
        ├── page.html 的 main
        │   ├── breadcrumbs.html
        │   ├── terms.html
        │   └── Markdown .Content
        │       └── _markup/render-codeblock.html
        ├── _partials/footer.html
        └── 有目录时：_partials/sidebar/right.html
        │
        ▼
public/ 中的 HTML、带指纹 CSS/JavaScript 和静态图标

模板负责构建期生成语义 HTML，CSS 负责视觉布局，JavaScript 只负责交互增强。这个边界使静态页面在脚本失败时仍然可以阅读。

站点配置如何驱动主题

站点根目录 hugo.toml 中与主题直接相关的配置如下：

配置被哪里使用
title、copyrighthead.html、header.html、footer.html
params.description、params.author首页 Hero 和 head 元数据
params.treeSearch决定左侧栏是否输出搜索框
menus.main生成顶栏的首页、标签、关于链接
taxonomies.tag = "tags"生成标签总览与标签详情页
markup.tableOfContents决定 .TableOfContents 收集 H2–H4
markup.highlight决定围栏代码、行号和 Chroma 类名
outputs为首页和栏目页额外生成 RSS

还有三个参数目前只是配置中保留的意图，没有被主题模板读取：

  • params.defaultTheme：实际初始主题由 head.html 按本地记录或系统偏好决定；
  • params.tocStartLevel 与 params.tocEndLevel：实际目录层级由 markup.tableOfContents.startLevel/endLevel 决定。

如果以后希望它们生效，需要在模板中显式读取，而不是只修改配置值。

同理，文章 Front Matter 中的 toc 当前也没有被模板读取。baseof.html 会根据文章是否实际生成了目录项自动决定右侧栏是否出现；仅设置 toc: false 还不能关闭目录。

哪些目录不应手工维护

  • node_modules/：由 npm install 生成；
  • .git/：由 Git 管理；
  • .hugo_build.lock：由 Hugo 运行时生成；
  • 主题或站点中的 public/：完整静态构建结果；
  • resources/_gen/：Hugo 资源缓存；
  • package-lock.json：由 npm 根据依赖变化更新；
  • assets/css/chroma.css：由 hugo gen chromastyles 重新生成。

这些文件与目录有的需要提交、有的不需要提交，但共同点是都不适合把内部内容当成手写业务源码逐项修改。

用页面包组织多级目录

Hugo 使用两种页面包：

  • _index.md 表示 branch bundle，也就是可以继续包含子目录和文章的目录；
  • index.md 表示 leaf bundle，也就是一篇文章及其图片、附件。

例如：

content/
└── 网络技术/
    ├── _index.md
    └── 网络协议/
        ├── _index.md
        └── HTTP/
            ├── index.md
            └── request-flow.png

这种结构可以继续向下嵌套。主题递归读取 Hugo 页面树，所以左侧导航不限制目录深度。

创建目录和文章

创建一个可继续嵌套的目录：

hugo new content 网络技术/网络协议/_index.md

创建一篇带独立资源目录的文章：

hugo new content 网络技术/网络协议/HTTP/index.md

文章图片直接放在 HTTP/ 目录内，然后使用相对路径：

![HTTP 请求流程](request-flow.png)

移动整篇文章时，正文与资源会一起移动。

排序和置顶

主题遵守以下顺序：

  1. 文件夹始终排在文章之前；
  2. 显式设置 weight 的项目优先，数值越小越靠前；
  3. 未设置 weight 的项目按日期倒序。

例如把文章置顶：

---
title: '重要文章'
weight: 1
---

草稿箱

旧博客中的草稿集中迁移到：

content/草稿箱/

它们继续保留 draft: true。正式构建不会出现草稿箱，开发预览时使用 -D：

hugo server -D -p 1314

主题交互

huilux-tree 提供：

  • 可递归展开的左侧文件树；
  • 只筛选文章与目录标题的即时搜索；
  • 可折叠的左侧导航和右侧文章目录；
  • 移动端抽屉导航；
  • 跟随系统并可手动切换的亮色、暗色主题；
  • H2–H4 文章目录和滚动高亮；
  • 对旧 admonition、typeit 短代码的兼容。

折叠状态、目录展开状态和颜色主题都保存在浏览器本地，下次访问会自动恢复。

本地预览与构建

开发预览：

cd /home/ming/blog/huilux
hugo server -D -p 1314

正式构建：

hugo --minify

生成的静态网站位于 public/，可以部署到任意静态托管服务。
