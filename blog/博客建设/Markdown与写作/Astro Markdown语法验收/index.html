Astro Markdown 语法验收

用一篇文章检查 HUILUX 的排版、Shiki 代码高亮、KaTeX 公式、图片和响应式细节。

内容时效

本文最后维护于21 天前，部分技术细节可能已经变化，请结合当前版本和官方文档核对。

这是一篇专门用于检查主题的文章。它不追求讲完某个技术话题，而是把常用 Markdown、Astro 内置 Shiki 代码高亮和 KaTeX 数学公式放在同一个页面里。切换明暗主题、缩放浏览器，再用手机宽度阅读一遍，就能快速发现样式回归。

验收目标：内容应当清晰、层次稳定、可以键盘访问，并且不应让页面产生水平滚动条。

行内排版

一个段落可以同时包含 粗体、斜体、粗斜体、已删除的文字以及 const theme = 'signal-path' 这样的行内代码。还可以显示转义字符：* 不是斜体，# 不是标题，<signal> 不是 HTML 标签。

补充的文本语义包括 高亮、插入内容、缩写 HTML、下标 H2O、上标 x2 以及键盘组合 Ctrl + K。

这里是站内的 Astro 标签，这里是 Astro 官方 Markdown 文档，这里则是可自动识别的链接：https://astro.build/。

验收清单

  1. 切换浅色和深色主题，观察正文、链接、表格、各种代码语言与行级标注。
  2. 用键盘打开折叠内容，并沿右侧目录跳转。
  3. 把视口调整到 390px，确认表格、公式与代码各自滚动。
  4. 检查图片 alt、链接焦点和文章目录的当前位置。
  5. 运行 npm run verify，确认内容 schema、类型和静态构建全部通过。

如果以上项目都正常，这条内容信号就已经完整连通。
